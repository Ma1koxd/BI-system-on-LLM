# Такт - производственная аналитика

Учебный сервис для начальника смены, мастера и технолога. Вопрос на русском языке задаёт условия выборки. Сервис пересчитывает таблицу, график и текстовый вывод по одной витрине. Все данные синтетические.

## Запуск демонстрации

Откройте `dist/index.html` в браузере. Демонстрационный разбор работает локально по правилам. Сервер, подключение к сети и установка пакетов для этого режима не нужны.

## Локальный режим с LLM

Понадобятся Node.js версии 20 или выше и работающий Ollama с локальной моделью, которая понимает русский язык и поддерживает структурированный ответ. В PowerShell из каталога проекта выполните команды для выбранной модели. Ниже приведён пример с Qwen.

```powershell
ollama pull qwen2.5:3b
$env:OLLAMA_MODEL = 'qwen2.5:3b'
node server.cjs
```

Откройте [локальный сервис](http://127.0.0.1:8765/). Имя настроенной модели появится под заголовком чата. Если Ollama ещё не запущен, запустите приложение Ollama или `ollama serve` в отдельном терминале. Чтобы использовать другой HTTP-порт для BI-сервиса, задайте переменную `PORT` перед запуском Node.js.

Сервер передаёт вопрос, фильтры предыдущего запроса и JSON-схему на локальный адрес Ollama `127.0.0.1:11434/api/chat`. Модель возвращает план анализа. Сервер проверяет типы, диапазоны, имена оборудования и допустимые метрики. Расчёт и отчёт выполняются по проверенному плану. При ошибке модели чат сообщает о ней и сохраняет предыдущий результат. [Формат структурированных ответов Ollama](https://docs.ollama.com/capabilities/structured-outputs).

## Сценарий демонстрации

1. Спросите «Где выпуск сильно отстаёт от плана и какой там процент брака за последние 5 смен?». В таблице останутся две смены с отставанием не менее 10 %. Первой будет дневная смена 17 ноября на линии А с выпуском 469 шт. при плане 720 шт.
2. Спросите «Покажи только ночные смены». Чат сохранит период и порог отставания. В этом срезе таких смен нет. Нажатие кнопки с круговой стрелкой в заголовке чата начнёт новый диалог.
3. В новом диалоге спросите «Выведи топ-3 станка по доле брака», затем «Сравни с прошлой неделей». В обоих периодах сравниваются станки из текущего рейтинга.
4. Спросите «Покажи простои длиннее 30 минут с причиной». Таблица покажет начало, конец, станок, длительность и зарегистрированную причину каждого события.
5. Для разбора выпуска по часам начните новый диалог и спросите «Выпуск по часам на линии А за 17.11.2026». На графике видны зона 90-100 % плана и отметки часов с простоем. Наведение на точку показывает показатели и изменение к предыдущему часу.

Дополнительные вопросы для демонстрации: «Средний выпуск за час по линиям», «Загрузка оборудования по станкам», «Брак по причине поверхность за последние 10 смен», «Выпуск по активным заказам на станке S-102». Для даты можно использовать форматы ГГГГ-ММ-ДД и ДД.ММ.ГГГГ. Кнопки показателей меняют исследуемую метрику. Пагинация под таблицей открывает остальные строки.

## Витрина и показатели

Витрина содержит 2016 почасовых записей, 42 смены и 4 станка. Станки S-101 и S-102 относятся к линии А, S-201 и S-202 к линии Б. Наблюдение начинается 29 октября 2026 года в 08:00 и заканчивается 19 ноября в 08:00. Дневная смена начинается в 08:00, ночная в 20:00. Время соответствует часам цеха. Генератор с фиксированным начальным значением воспроизводит одинаковые записи при каждом открытии.

| Показатель | Расчёт |
| --- | --- |
| Выпуск | Сумма годных деталей |
| Отклонение, % | 100 × (выпуск − план) / план |
| Доля брака, % | 100 × брак / (выпуск + весь брак) |
| Средний выпуск за час | Выпуск / число различных часов, вошедших в выборку |
| Простои | Сумма минут простоя всех выбранных станков |
| Загрузка, % | 100 × (доступные машино-минуты − простои) / доступные машино-минуты |

Для брака доступны причины «Размер», «Поверхность» и «Геометрия». Фильтр причины меняет числитель доли. Доля по интервалу вычисляется по суммам деталей. Для сравнения с прошлой неделей время сдвигается на 168 часов. Машины и часы текущей выборки определяют область сравнения. Для периода без доступной истории в таблице выводится прочерк.

Окно последних N смен задаётся до фильтров линии, типа смены и заказа. При запросе отстающих смен или рейтинга карточки и график строятся по отобранным группам. В журнале порог длительности действует на отдельные события. Карточки над журналом характеризуют весь выбранный период. Минуты начала и конца события записаны отдельно, показатели выпуска и брака имеют часовую детализацию. Рекомендации предлагают проверку, причинная связь между простоем и изменением выпуска требует подтверждения.

## Исходный код

- `dist/engine.js` формирует витрину, разбирает вопросы в деморежиме, фильтрует и агрегирует записи, сравнивает периоды и составляет выводы.
- `dist/app.js` управляет контекстом диалога, строит график и таблицу.
- `dist/index.html` и `dist/style.css` задают структуру и адаптивное оформление панели.
- `server.cjs` обслуживает интерфейс и обращается к локальной LLM.
- `checks.cjs` проверяет расчёты и сценарии из задания. Запуск - `node checks.cjs`.
