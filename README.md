# Такт BI

Python-сервис для анализа выпуска, брака, простоев и загрузки оборудования. Пользователь задаёт вопрос по-русски, получает отчёт и уточняет условия в чате. Сервер выбирает данные из SQLite, формирует таблицу JSON и строит PNG-график с помощью Matplotlib. Полная формулировка задания приведена в [THEME.md](THEME.md).

## Запуск через Docker

Нужен работающий Docker Engine с Docker Compose v2 или новее. В Windows подойдёт Docker Desktop в режиме Linux-контейнеров. Откройте PowerShell в каталоге с `compose.yaml`.

**Демонстрация без ключа:**

```powershell
docker compose up --build
```

Откройте [панель цеха](http://localhost:8765/). Первый запуск создаёт учебную SQLite-витрину в именованном томе `workshop-data`. Демонстрационный режим разбирает поддерживаемые вопросы правилами и выполняет те же Python-функции и SQL-запросы, что и LLM-режим.

**Чат с моделью через OpenRouter:**

1. Скопируйте шаблон настроек командой `Copy-Item .env.example .env` (один раз, если файла ещё нет).
2. Впишите свой ключ в `LLM_API_KEY` в файле `.env`. Ключ нужен только серверу. Файл исключён из Git и контекста сборки Docker.
3. Запустите `docker compose up --build -d`. После изменения настроек уже запущенной версии выполните `docker compose up -d --force-recreate`.
4. Откройте [панель](http://localhost:8765/). Под заголовком чата появится имя настроенной модели. Для проверки реального подключения отправьте вопрос «Где выпуск отстаёт от плана за последние 5 смен?».

| Переменная | Пример для OpenRouter | Пример для OpenAI |
| --- | --- | --- |
| `LLM_BASE_URL` | `https://openrouter.ai/api/v1` | `https://api.openai.com/v1` |
| `LLM_MODEL` | `openai/gpt-4o-mini` | `gpt-4o-mini` |
| `LLM_API_KEY` | Ключ OpenRouter | Ключ OpenAI |

Для корпоративного сервиса укажите его базовый URL, ключ и идентификатор модели в этих же переменных. Нужна совместимость с Chat Completions, вызовами функций (`tools`, `tool_choice`) и строгим `response_format.type=json_schema`. В качестве переменной ключа для стандартного OpenRouter также поддерживается `OPENROUTER_API_KEY`, для OpenAI - `OPENAI_API_KEY`. Ошибки модели, авторизации и лимитов отображаются в чате. [Function calling в OpenRouter](https://openrouter.ai/docs/guides/features/tool-calling) и [Structured Outputs](https://openrouter.ai/docs/guides/features/structured-outputs).

Для остановки выполните `docker compose down`. Именованный том сохраняет базу между запусками. Журнал сервера доступен через `docker compose logs -f takt`. Опубликованная HTML-демонстрация предыдущей версии имеет свою учебную витрину. Адрес новой серверной версии при локальном запуске - `http://localhost:8765/`.

## Как проверить работу

1. Спросите «Где выпуск сильно отстаёт от плана и какой там процент брака за последние 5 смен?». Таблица содержит две строки. В дневную смену 17 ноября на линии А выпустили 469 годных деталей при плане 720, отклонение составило -34,9 %, доля брака 15,6 %.
2. Спросите «Покажи только ночные смены». Период и критерий отставания сохранятся. В этих пяти сменах ночных смен с отставанием от 10 % нет.
3. Начните новый диалог кнопкой в заголовке чата. Спросите «Топ-3 станка по доле брака», затем «Сравни с прошлой неделей». Сервис найдёт показатели тех же станков за те же часы семью днями раньше.
4. Спросите «Покажи простои длиннее 30 минут с причиной». В журнале есть простой S-102 длительностью 45 минут. Для почасового разбора задайте отдельный вопрос «Выпуск по часам на линии А за 17.11.2026».

График «По часам» показывает для выпуска зону 90-100 % плана. Маркеры внизу отмечают часы с остановками. Кнопка выгрузки JSON у таблицы сохраняет все строки выбранного отчёта.

## Как проходит запрос

1. Браузер отправляет вопрос и фильтры предыдущего результата на `POST /api/chat`. В LLM-режиме Python SDK `openai` вызывает настроенный сервис. Первый ответ модели выбирает одну именованную функцию с аргументами или запрашивает уточнение.
2. Сервер проверяет имя и параметры функции, вычисляет показатели по SQLite и формирует строки, временной ряд, факты и рекомендацию. Ручные фильтры интерфейса вызывают `POST /api/report` и выполняют расчёт без обращения к провайдеру.
3. При втором обращении к LLM сервер передаёт результат функции в виде каталога подтверждённых фактов и рекомендаций. Через Structured Outputs модель возвращает их идентификаторы по строгой JSON Schema. Сервер проверяет идентификаторы и составляет текст из рассчитанных значений. Строки таблицы и значения графика поступают непосредственно из расчётной функции.
4. Matplotlib рендерит временной ряд на сервере через Agg. Ответ API содержит PNG в base64 и подпись. Контекст следующего вопроса находится в `filters`. У разных вкладок независимые диалоги.

| Функция для function calling | Назначение |
| --- | --- |
| `shift_summary` | План/факт по сменам, линиям, станкам. Суммы, доли, средний выпуск за час, фильтр статуса заказов |
| `plan_shortfalls` | Отставание от плана и брак, сортировка по отклонению, порог по умолчанию 10 % |
| `hourly_output` | Выпуск по часам, план, простои и изменение к предыдущему последовательному часу через SQL `LAG` |
| `machine_ranking` | Рейтинг станков по выбранному показателю |
| `compare_week` | Сопоставление текущей выборки с эквивалентными часами неделей ранее |
| `downtime_events` | Отдельные остановки с временем, длительностью и причиной. Порог сравнивается строго |
| `defect_breakdown` | Брак по причинам, числу деталей и доле от всего выпуска |
| `equipment_load` | Взвешенная загрузка за период |

## Формат JSON и API

Интерактивная документация после запуска: [Swagger UI](http://localhost:8765/docs), [полная схема OpenAPI](http://localhost:8765/openapi.json). Версия формата успешного отчёта - `schema_version: "1.0"`.

- `GET /api/config` возвращает режим чата и имя модели.
- `GET /api/health` показывает готовность HTTP-сервера после инициализации базы.
- `POST /api/chat` принимает `{"question":"Покажи только ночные смены","context":{}}`. Для уточнения передавайте предыдущие `filters` в `context`.
- `POST /api/report` принимает `{"tool":"plan_shortfalls","arguments":{"count":5},"context":{}}`.

Оба POST-маршрута возвращают `tool`, `mode`, `model`, `filters`, `metric_label`, `unit`, `kpis`, `table`, `series`, `chart`, `facts`, `summary` и `recommendations`. Таблица имеет две части: `columns` с ключом, подписью и единицей измерения каждого столбца и `rows` с данными. Ключи в каждой строке совпадают с ключами столбцов. Числа остаются числами JSON. Недоступное значение представлено `null`, пустая выборка - массивом `rows: []`. Для ручного запроса `mode` равен `direct`, для чата - `llm` или `demo`.

Получить полную таблицу из PowerShell:

```powershell
$body = '{"tool":"plan_shortfalls","arguments":{"count":5},"context":{}}'
$report = Invoke-RestMethod -Method Post -Uri 'http://localhost:8765/api/report' -ContentType 'application/json' -Body $body
$report.table | ConvertTo-Json -Depth 5
```

Пример одной строки из такого ответа (поля процентов закругляются только при показе в интерфейсе):

```json
{"shift_id":"17.11 · день","line":"А","good":469,"plan":720,"deviation":-34.861111111111114,"bad":87,"rate":15.647482014388489,"down":267}
```

## Учебные данные и формулы

SQLite хранит 2016 записей: 42 смены по 12 часов на четырёх станках с 29 октября 2026 года 08:00 до 19 ноября 08:00 по времени цеха. Линия А содержит S-101 и S-102, линия Б - S-201 и S-202. Одна запись описывает час одного станка. База заполняется один раз при инициализации.

| Показатель | Расчёт |
| --- | --- |
| Выпуск | Сумма годных деталей |
| Отклонение, % | 100 × (выпуск - план) / план |
| Доля брака, % | 100 × брак / (годные детали + весь брак) |
| Средний часовой выпуск | Выпуск по выбранным станкам / число различных представленных часов |
| Простои | Сумма машино-минут простоя |
| Загрузка, % | 100 × (доступные машино-минуты - простои) / доступные машино-минуты |

Фильтр причины брака меняет числитель доли. При неполном покрытии недельного сравнения историческое значение для группы отсутствует. В журнале порог длительности относится к событиям и графику остановок, а KPI наверху характеризуют весь выбранный период. Качество известно с часовой точностью. Причину отдельного простоя можно проверить по полям журнала.

## Разработка без Docker

Для запуска нужен Python 3.12. Из каталога проекта в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m uvicorn app:app --host 127.0.0.1 --port 8765
```

В Linux и macOS эквивалентные команды используют `python3.12 -m venv .venv` и `.venv/bin/python`. Локально файл БД по умолчанию находится в `data/workshop.sqlite3`. Путь можно переопределить переменной `DATABASE_PATH`. Файл `dist/offline.html` содержит автономную HTML-демонстрацию для открытия без Python.

Тесты запускаются из каталога проекта:

```powershell
.\.venv\Scripts\python -m unittest discover -s tests -v
```

Тесты проверяют функции, API, JSON-таблицы, изображения и реальный HTTP-протокол SDK на локальной имитации провайдера. Для проверки выбранной коммерческой модели используйте собственный ключ.
