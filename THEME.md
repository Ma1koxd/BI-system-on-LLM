# Тема 4. Разработка интеллектуальной BI-системы на основе LLM для анализа производственной эффективности цеха

## Цель

Создать сервис, в котором начальник смены, технолог или мастер получает аналитику производственного участка на естественном языке. Пользователь может узнать выпуск продукции, долю брака, продолжительность простоев и загрузку оборудования без написания SQL, скриптов и ручного сведения отчётов.

## Результат

Интерфейс объединяет чат и панель визуализации. В ответ на вопрос система возвращает таблицу показателей по смене, линии или агрегату, один или два графика и короткий текст с выводами и рекомендациями. Факты в отчёте можно сверить со значениями в таблице и записями журнала.

## Требования к системе

1. Выделять из вопроса период, участок, линию, станок, метрику и способ сравнения. Поддерживать сравнение с планом, с прошлой неделей и между сменами.
2. Выполнять фильтрацию и расчёты. Поддерживать сумму, среднее и долю, динамику по часам с использованием оконных функций, отбор активных заказов и брака по причинам. Для учебной реализации допускаются подготовленные витрины данных.
3. Возвращать таблицу с полями «Смена / участок», «Выпуск», «План», «Отклонение», «Брак» и «Простои». Использовать машиночитаемый JSON с описанием столбцов, единиц и строк.
4. Строить график выпуска по часам с зоной плановых значений и отметками простоев. Для анализа плана показывать план и факт по сменам.
5. Объяснять наблюдения с опорой на данные. Для разбора простоя привести интервал, станок, длительность, причину из журнала и долю брака с указанием периода, за который она рассчитана. Рекомендация может предложить проверить подачу материала, конвейер или журнал инцидентов. Причинные гипотезы требуют проверки.
6. Учитывать контекст уточняющих вопросов: «Покажи только ночные смены», «Выведи топ-3 станка по доле брака», «Сравни с прошлой неделей», «Покажи простои длиннее 30 минут с причиной».

## Пример применения

Пользователь спрашивает: «Покажи, где выпуск сильно отстаёт от плана и какой там процент брака за последние 5 смен».

Система выделяет окно из пяти смен, группирует показатели по смене и участку, рассчитывает отклонение от плана и долю брака. Отставание в этом прототипе считается существенным начиная с 10 %. Худшие строки идут первыми.

- Доля брака, % = 100 × брак / (выпуск годных деталей + брак).
- Отклонение от плана, % = 100 × (выпуск годных деталей - план) / план.

Пользователь видит таблицу, график план/факт и вывод с величиной отклонения и долей брака. Затем он может открыть журнал простоев для проблемной линии, проверить состояние станка и сопоставить причины остановок со сменным заданием. По результатам проверки мастер решает, требуется ли перераспределение заказов.

Пример формулировки из исходного задания: «Наибольшее отставание - в смене 2 на участке А (-28 %), доля брака - 16 %; в смене 4 на участке Б (-23 %), доля брака - 13 %». По этим данным можно предложить проверить загрузку персонала и состояние станков, сопоставить наблюдения с журналом простоев и инцидентов, рассмотреть перераспределение заказов.

Другой пример из задания связывает наблюдения по времени: в интервале 14:00-15:30 зарегистрирован простой станка S-102 длительностью 45 минут, доля брака на линии А за период составляет 18 %. Возможная причина - сбой подачи материала. Предлагается проверить конвейер и журнал инцидентов. Числа в этих двух иллюстрациях относятся к условию задания. В рабочей демонстрации значения рассчитываются по учебной витрине.

## Реализация в этом проекте

Сервис на Python 3 использует OpenAI-совместимый API. Расчётные функции читают SQLite, графики строит Matplotlib. Модель выбирает функцию и её параметры через function calling, а затем использует Structured Outputs для выбора подтверждённых выводов. Запуск и настройка через Docker Compose описаны в [README](README.md).
